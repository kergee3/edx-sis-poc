# Moji_Joho(文字情報基盤)由来の氏名文字の JIS X 0213 への変換方針

**― IVDコレクション間対応の調査結果と、基底文字への縮退方針の決定 ―**

作成日: 2026-07-03
ステータス: 方針決定済み(変換先を JIS X 0213 の基底文字に限定)

---

## 1. 概要

政府関係データベースから提供される氏名(苗字)データは、文字情報基盤(MJ文字図形名、および Unicode IVD の Moji_Joho コレクションの IVS)で規定されている。これを、教育現場で使われる校務支援システム・学習支援システムで扱えるようにするため、JIS X 0213 で規定される文字への変換方式を検討した。

当初は、単純な基底文字への変換に加え、Variation Selector(VS)を用いた異体字表現(Adobe-Japan1 コレクションの IVS への付け替えを含む)の利用可能性も模索した。しかし本調査の結果、以下の 2 点が判明したため、**変換先は JIS X 0213 の基底文字(VS を付与しない符号位置)に限定する**方針とした。

1. **IVD 自体は、コレクション間の「同じ字形」の対応を定義していない**。Moji_Joho の IVS と Adobe-Japan1 の IVS の間に、機械可読な公式対応表は存在しない。
2. **複数の Moji_Joho 文字図形が Adobe-Japan1 の 1 グリフに対応せざるを得ないケースが大量にある**。両コレクションに対応がある 13,261 の UCS 符号位置のうち、**3,771 符号位置(28.4%)** では MJ 文字図形数が Adobe-Japan1 のグリフ数を上回っており(MJ 図形 8,692 に対し AJ1 グリフ 3,820)、多対 1 の縮退が構造的に避けられない(§4.2)。

加えて実務上の理由として、校務支援・学習支援アプリの多くがそもそも IVS を前提とした処理(検索・照合・入力・帳票出力での VS の保持)に対応していないことがある。IVS 付きデータを非対応アプリに渡すと、VS が別文字として扱われる・削除される・文字化けするなどの障害が予想され、氏名という業務上最も事故が許されないデータでのリスクは許容できない。

## 2. 背景

### 2.1 データの流れ

```
政府関係DB(氏名: MJ文字図形名 / Moji_Joho IVS)
        │
        ▼  本変換処理(MJ → JIS X 0213 基底文字)
        │    ・機械的に一意に決まる場合は自動変換
        │    ・複数候補がある場合は利用者(管理者・本人)が選択
        ▼
校務支援システム / 学習支援システム(JIS X 0213 の範囲で運用)
```

### 2.2 関係する文字集合・規格

| 名称 | 規模(漢字) | 性格 |
|---|---|---|
| JIS X 0213:2004 | 10,050 字(第1〜4水準) | 国内標準。包摂規準により異体字を 1 符号位置に統合 |
| Adobe-Japan1-7 | 14,664 グリフ(漢字) | Adobe 策定の DTP 向けグリフ集合。全漢字グリフに IVS を登録 |
| 文字情報基盤(MJ) | 58,862 図形 | 戸籍統一文字・住基ネット統一文字等を包含する行政向け文字図形集合 |

MJ は戸籍実務で区別されてきた字形差(しんにょうの点の数、「艹」の画数等)を図形単位で保持するため、JIS X 0213 や Adobe-Japan1 より字形の粒度がはるかに細かい。この粒度差こそが本件の変換を「多対 1 の縮退」にする根本要因である。

## 3. 技術的前提: IVD と各コレクションの登録方針

Unicode の IVD(Ideographic Variation Database)は、基底文字 + VS(U+E0100〜)の並び(IVS)を「コレクション」単位で登録する仕組みである(UTS #37)。重要な性質として:

- **セレクタの割当てはコレクションごとに独立**している。Moji_Joho は先行する Hanyo-Denshi コレクションとはセレクタを共有・再利用しているが、Adobe-Japan1 とは共有していない。
- したがって、**見た目が同じ字形でも、コレクションが違えば別のセレクタになる**。IVD にはコレクションをまたいだ「この IVS とあの IVS は同じ字形」という情報は存在しない。
- 登録方針も異なる。Adobe-Japan1 は収録する全漢字グリフに IVS を登録するのに対し、Moji_Joho は **1 つの UCS 符号位置に複数の MJ 図形が対応する場合にのみ** IVS を登録する。このため IVS を持たない MJ 図形も多数ある(調査時点で、JIS X 0213 例示字形に対応する MJ 図形 10,909 件のうち 6,752 件が IVS 未登録。§4.3)。

**例: 葛(U+845B)**。Adobe-Japan1 は E0100(CID+1481、いわゆる JIS90 字形)と E0101(CID+7652、JIS2004 字形)の 2 系列、Moji_Joho は E0102〜E0108 の 7 図形(MJ022335〜MJ022341)を登録している。字形として MJ022335(U+845B U+E0102)と CID+1481(U+845B U+E0100)は対応するが、この対応は IVD のどこにも記述されていない。

## 4. 調査結果

調査には、MJ文字情報一覧表・MJ縮退マップ・IVD・aj17-kanji.txt 等を SQLite に統合した公開データベース mojidata(v1.8.1)を使用した(出典は §8)。

### 4.1 コレクション間対応表は「作れる部分」と「作れない部分」に分かれる

JIS X 0213 の集合に限定した場合、**JIS X 0213:2004 の例示字形レベル**では厳密な 1:1 対応表が機械的に生成できる。根拠は、MJ文字情報一覧表の「X0213 包摂区分 = 0」(当該 MJ 図形が JIS の例示字形に包摂規準の適用なしで対応することを示す)と、Adobe-Japan1 側の UniJIS2004 CMap(UCS→CID)を、面区点 + UCS で突き合わせられることにある。この方法で 10,909 行の対応表を生成済みである(付属成果物 `jisx0213_mj_aj1_2004form.csv`)。葛では MJ022336(E0103)↔ CID+7652(E0101)が例示字形ペアとなる。

一方、**例示字形以外の字形ペア**(冒頭の MJ022335 ↔ CID+1481 のような JIS90 字形どうしの対応を含む)は、機械的には確定できず、字形の目視照合または既存の照合研究に依存する。この問題は先行研究でも指摘されており、安岡(2017)は小塚明朝(CID)と IPAmj明朝(MJ)の字形比較により 13,856 組の 1:1 対応表を作成したが、その中でも「1:1 対応とするには微妙」なケースが残ること、また Moji_Joho の IVS が Hanyo-Denshi で一旦包摂された字体群を一部「再分離」する形で構成されているため、Adobe-Japan1 の IVS と Moji_Joho の IVS の対応表の作成はかなり難しいことを明記している(出典 [6])。

なお JIS90 字形と JIS2004 字形で Adobe-Japan1 の CID が異なる文字は 170 字あり、この範囲の照合対象リストも生成済みである(付属成果物 `jis90form_needs_glyph_matching.csv`)。

### 4.2 多対 1 対応の定量(本方針決定の根拠データ)

「複数の Moji_Joho 文字が Adobe-Japan1 の 1 文字(1 グリフ)に対応する例」の件数について。コレクション間の字形同値データが存在しないため厳密なグリフ単位の件数は確定できないが、**鳩の巣論法による下限**として次が言える。

| 指標 | 件数 |
|---|---|
| MJ 文字図形 総数 | 58,862 |
| うち「対応する UCS」を持つもの | 58,859 |
| 同一 UCS に 2 図形以上の MJ が対応する UCS 符号位置 | **5,072**(該当 MJ 図形 11,413) |
| 1 UCS あたりの MJ 図形数の最大 | **16 図形(邉 U+9089)** |
| MJ と Adobe-Japan1 の両方に対応がある UCS 符号位置 | 13,261 |
| うち MJ 図形数 > AJ1 グリフ数 となる UCS(多対 1 が不可避) | **3,771(28.4%)** |
| その範囲の内訳 | MJ 図形 8,692 に対し AJ1 グリフ 3,820 |

つまり、両コレクションが重なる範囲だけでも約 3,800 符号位置で「複数の MJ 図形 → 1 つの AJ1 グリフ」の縮退が数の上で避けられない。Adobe-Japan1 の IVS へ付け替える方式を採ったとしても、氏名の字形情報は保存できないことがこの数字から確定する。

代表例の **邉(U+9089)** は MJ 図形が 16 種(MJ026190〜MJ026197、MJ058866、MJ060234〜MJ060239、MJ060248)あるのに対し、JIS X 0213 では 1-78-21 の 1 符号位置に縮退される。

### 4.3 JIS X 0213 への縮退カバレッジ

変換先を JIS X 0213 基底文字に限定した場合の到達可能性を、MJ文字情報一覧表の X0213 フィールドと MJ縮退マップ(縮退X0213)で集計した。

| 変換経路 | MJ 図形数 |
|---|---|
| ① MJ一覧表の X0213 フィールドで直接 JIS 面区点に対応 | 13,707(面区点 10,054) |
| ② MJ縮退マップのいずれかの規則で「縮退X0213」に到達(①を包含) | **35,851(60.9%)** |
| JIS X 0213 へ変換不能(①②いずれの経路もなし) | **23,011(39.1%)** |
| 縮退先の面区点が複数候補になる MJ 図形 | **7,167** |
| 同一面区点へ複数の MJ 図形が縮退される面区点(①の範囲) | 2,887 |

MJ縮退マップの規則別のテーブル規模(mojidata 収載分の行数)は次のとおり。規則には確度の序列があり、変換処理の優先順位設計にそのまま使える。

| 縮退規則 | 行数 | 性格 |
|---|---|---|
| JIS包摂規準・UCS統合規則 | 14,515 | 最も確実(符号規格上の同一視) |
| 戸籍統一文字情報(親字・正字) | 18,089 | 戸籍実務の正字関係。「ホップ数」列あり |
| 法務省告示582号 別表第四(一/二) | 5,006 / 7,562 | 在留関係の正字化規則。「順位」列あり |
| 民一2842号通達 別表(俗字/別字/無印) | 233 / 150 / 618 | 誤字俗字→正字 |
| 民二5202号通知 別表 | 138 | 正字俗字等対照 |
| 読み・字形による類推 | 413 | 確度低め |
| 辞書類等による関連字 | 15,958 | 最も緩い(参考扱い推奨) |

なお「変換不能 23,011 図形」は MJ 全体に対する数字であり、実際の苗字データに出現する文字の大半は戸籍統一文字由来で、戸籍系の縮退規則にカバーされることが期待できる。実データ受領後に出現文字ベースでのカバレッジを再計測すべきである(§6 残課題)。

## 5. 方針: JIS X 0213 基底文字への限定

以上を踏まえた決定事項。

**決定**: 政府 DB 由来の MJ 氏名文字は、JIS X 0213 で規定される文字の**基底文字(VS なしの符号位置)**へ変換して校務支援・学習支援システムに渡す。IVS(Moji_Joho のまま、または Adobe-Japan1 への付け替え)は採用しない。

**理由**:

1. **受け側アプリの現実**: 校務支援・学習支援アプリの多くは IVS を前提とした処理(照合・検索・入力・印字での VS 保持)に対応していない。VS が落ちる・二重に数えられる・化ける等の事故リスクが氏名データでは許容できない。
2. **コレクション間対応の不在**: IVD はコレクション間の字形対応を定義しておらず(§3)、Moji_Joho → Adobe-Japan1 の IVS 付け替えには公式・機械可読な根拠データがない。例示字形レベル以外は目視照合に依存する(§4.1)。
3. **多対 1 の構造**: 仮に付け替えても、少なくとも 3,771 符号位置で複数 MJ 図形が 1 つの AJ1 グリフに縮退する(§4.2)。IVS を維持するコストに見合う字形保存効果が得られない。
4. **JIS X 0213 の設計思想との整合**: JIS X 0213 は包摂を前提とした文字符号であり、基底文字への縮退は規格の設計思想(包摂規準)に沿った正規化である。MJ縮退マップという公式の縮退規則群が整備されており、変換の根拠を規則名として記録・説明できる。

**トレードオフ(受容するリスク)**: 基底文字への縮退により、本人確認書類(戸籍・住民票等)上の字形と画面・帳票上の字形が異なって見えるケースが必然的に生じる(例: 「邊」「邉」系の各種字形 → 1-78-20/1-78-21 の例示字形で表示)。これは仕様として明示し、必要に応じて「原字形は MJ 文字図形名で別フィールドに保持する」(§6)ことで将来の可逆性を確保する。

## 6. 変換処理の設計指針

変換パイプラインは次の優先順位で構成する。

1. **経路 A(無変換)**: MJ 図形の「対応する UCS」が JIS X 0213 の符号位置を持つ場合、その基底文字をそのまま採用する(VS は付与しない)。MJ一覧表の X0213 フィールドが埋まっている 13,707 図形はここで確定する。
2. **経路 B(縮退マップ)**: 経路 A で決まらない場合、MJ縮退マップの「縮退X0213」を規則の確度順(JIS包摂規準・UCS統合規則 → 戸籍統一文字情報 → 法務省告示582号 → 民一2842号・民二5202号 → 類推・関連字)に適用する。戸籍系の「ホップ数」、告示582号の「順位」は候補の並び順に使う。
3. **利用者選択**: 縮退先が複数候補になる 7,167 図形、および確度の低い規則(類推・関連字)でのみ到達する場合は、自動確定せず候補を提示して利用者(校務担当者または本人・保護者)が選択する。選択結果は監査可能な形で記録する。
4. **変換不能**: どの経路でも JIS X 0213 に到達しない場合は、代替表記(ひらがな表記等)の運用ルールに委ねる。件数は実データで要計測。
5. **原情報の保持**: いずれの経路でも、**元の MJ 文字図形名(例: MJ026190)を正規化前の値として別カラムに保持する**。これにより縮退は非可逆でも、データとしては可逆になり、将来 IVS 対応環境が整った際の再変換や、本人確認時の照合に使える。DB スキーマ上は氏名カラムに `_mj`(原字形)と `_jis`(縮退後)の系列を持たせる設計が素直である。

実装面では、mojidata(npm: `@mandel59/mojidata`)が MJ一覧表・MJ縮退マップ・IVD・aj17-kanji.txt を単一の SQLite(`moji.db`)として配布しており、上記の経路 A/B は `mji` テーブルと `mjsm_*` テーブルへの JOIN で実装できる。本調査の集計もすべてこの DB 上の SQL で再現可能である。
